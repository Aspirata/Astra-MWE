# Astra MWE v0.1.0 Release Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current working tree into the clean, tested Astra MWE `v0.1.0` source release and fast-forward it into `Main`.

**Architecture:** Preserve the existing Go/Wails/WebGL application and change only release identity, public documentation, repository hygiene, and generated release metadata. Keep the canonical build paths under `scripts/`, retain source artwork, remove reproducible local output, and use the existing packaging tests as the executable release-name contract.

**Tech Stack:** Go 1.25, Wails v2, TypeScript 7, Vite 8, Three.js, GitHub Actions, PowerShell and Bash build scripts.

**Spec:** `docs/release-preparation-design.md`

## Global Constraints

- The public release version is exactly `0.1.0`; no tracked file may contain `poc` or `proof of concept`, case-insensitively.
- The dark GUI remains a product requirement.
- Build targets remain Windows x64, Windows ARM64, Linux x64, and Linux ARM64.
- Build success must not be described as verified runtime support.
- Worlds are read only, and Minecraft/client/mod/resource/user data must not enter Git or release archives.
- The final move to `Main` must be fast-forward only; no history rewrite and no release tag.
